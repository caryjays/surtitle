## Where things stand

Direction is set in the [roadmap](roadmap.md): an open-source, presenter-controlled caption layer pairing English with one other language per session, Japanese first, then Romance languages, Chinese, Korean and German, each behind a written gate. Stage 0 is in: the pair is configured by `LANGUAGE_PAIR` with one profile per language in `profiles/languages.json`, and English and Japanese are the only profiles; see [language pair](../log/2026-10-27-language-pair.md). The gate runner, the replay script and the translation eval take a gate or pair too, and profiles say whether a language writes spaces; see [gate tooling](../log/2026-11-10-gate-tooling.md). Still English and Japanese only: fixture preparation, the public translation cases and required terms, the language simulator and the development corpus. No language is added until Japanese passes its [gate](gates.md), whose targets and tooling exist. Spanish is the pilot for stage 2, ahead of French and Italian. Its first public and non-speech run failed in both segmentation modes; see [the entry](../log/2026-10-28-japanese-gate.md). Rolling passes every target the public and non-speech material measures; see [settle at lock](../log/2026-11-04-settle-at-lock.md) and [noise confirm](../log/2026-11-04-noise-confirm.md). Its first held-out run failed, mostly because the model's own one-pass decode missed the absolute targets on that material; see [held-out gate](../log/2026-11-06-held-out-gate.md). The held-out targets are now differences from that decode, live error at most 1.5 points and deletions at most 1.0 point over it; by those, the 2026-11-06 run passes English and fails Japanese, mostly on one talk; see [held-out targets](../log/2026-11-10-held-out-targets.md). That talk loses speech to Whisper looping on short stretches, not yet fixed, and showed rows outside the pair, which rolling Auto no longer locks after the worker retries such a window in the pair; simulated only; see [other languages](../log/2026-11-10-other-languages.md). Turns was not rerun.

The default profile is local Turbo Q4 with translation off. The listen profile, local recognition with cloud translation, has been used at a live conference with OpenAI Terra. An Anthropic Haiku 5.5 translator exists behind `TRANSLATION_PROVIDER=anthropic` and has only run against fake responses; see [its log entry](../log/2026-10-26-anthropic-translator.md). `pnpm eval:translation` compares OpenAI, Anthropic and local chat-completions translators on frozen public recognizer output; its first paid run found Haiku 5.5 level with Terra on quality and speed at about a twelfth of the cost, Sonnet 5.5 slightly better with a slow tail, and no model repairing recognition errors that need domain inference. See [the eval entry](../log/2026-10-26-translation-eval.md) and [the first results](../log/2026-10-26-first-translation-eval.md).

The [state review](../log/2026-11-10-state-review.md) verifies typechecking, the fake-provider tests, Python unit tests, build and synthetic browser smoke. It reproduced two rolling lifecycle defects, both fixed with adapter and controller regression tests: recalibration no longer lets speech heard before it become a row, and a rolling row keeps the direction it was heard in; see [rolling lifecycle fixes](../log/2026-11-10-rolling-lifecycle-fixes.md). Its other recommendations that needed no decision are in too: recalibration keeps finished rows, diagnostics record per-turn input level, applied capture settings and display pacing, `pnpm diag:latency` reports speech to displayed translation, and gate runs record their gate file and an implementation digest; see [reliability and measurement](../log/2026-11-10-reliability-and-measurement.md). `pnpm check`, the Python unit tests, the synthetic browser smoke and the rolling browser smoke with the real recognizer pass. None of the new diagnostics has been read from a real session yet. Real-model browser checks were not rerun; their previous verification is recorded in [the review](../log/2026-10-26-review-and-wiki.md) and [the public split](../log/2026-10-26-public-private-split.md).

Observed in the field by the maintainer:

- Lecture and Q&A with about 50 people on shared Wi-Fi: local recognition smooth; most translations readable including loanwords; translation lag of 2 to 3 s acceptable; some loanword phrases upset language detection; proper names confused.
- Breakout and group sessions: heavy false rejection. In the last logged interval 39 of 51 candidates were rejected, 30 of them by the speech gate before Whisper, with the energy gate threshold at its 0.004 floor. Raising the hardware input level helped noticeably. The final capture failure was an intentional unplug.

Not verified: local translation quality, and its effect on recognition timing with a real microphone; Haiku 5.5 translation quality, latency and refusal rate against Terra; OBS Browser Source rehearsal and browser-to-terminal scene continuity; the fixed physical-microphone silence path; a lecture-length soak under thermal load; measured end-of-speech to display latency; held-out accuracy beyond the tiny tuning set.

Experiment: the controlled noisy-Japanese run promoted nothing. Weaker gates matched baseline, faster previews did not speed finals, an 8 s cap hurt accuracy, and the room's rejection was not reproduced. See [NOISY-EXPERIMENT](../log/NOISY-EXPERIMENT.md).

## Open problems, ranked

1. Group-speech false rejection. Two untested hypotheses from the 2026-10-26 code review: Chrome's `echoCancellation` and `noiseSuppression` are hardcoded on in `apps/web/control.ts` and attenuate distant or overlapping speech; and audio reaches Silero with no level normalization while field levels were far below the faint fixture of about 0.015 RMS. Each turn trace now carries `inputRms` and `inputPeak`, and a `capture` diagnostics event records what the browser applied to the track. Next: read both from a room session; the source profiles in [lanes](lanes.md) replace separate toggles for the two Chrome flags; sweep faint fixtures to −18, −24 and −30 dB offline; if the gate rejects, trial deterministic per-turn gain in the worker before the gate.
2. Capture hard-fails on recoverable local conditions. A third queued final or one 12 s inference timeout requires a manual Start. Candidate: a visible automatic worker restart, and dropping the oldest queued final as `skipped`.
3. First text waits up to 12 s on continuous speech. Previews do not shorten first finals. A speech-aware boundary would need the gate on the Node side.
4. Language drift and proper names in Japanese Q&A. Forced Lecture mode is the workaround.
5. Minor: snapshots are serialized once per client per tick; a pause that exceeds its drain window reports "recognition unavailable"; torch is installed only for a 2 MB VAD model.

## Standing priorities

- Local recognition stays a hard requirement. Cloud recognition is not a substitute.
- Live defaults stay frozen until a controlled comparison shows a benefit.
- No paid calls, audience recording, remote exposure or publishing without explicit authorization.
- The OBS presentation stack comes after the personal companion is reliable.
