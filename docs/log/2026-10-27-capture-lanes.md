# Capture lanes

2026-10-27. A planning session after [product direction](2026-10-27-product-direction.md). No code changed; `pnpm docs:check` ran.

## What was done

The maintainer proposed four usage setups. Review added a fifth, the attendee listening to someone else's talk in person, which the earlier identity named but no setup covered. Hybrid and livestreamed events were folded in as a second output on a stage lane, and slide-video audio as a known edge of the direct stage. The five were named Remote call, Hosted stage, Direct stage, Open floor and Audience seat and written up in [lanes](../wiki/lanes.md), with four decisions in [decisions](../wiki/decisions.md).

## Effect on the plan

- Source profiles replace the planned capture toggles in the [status](../wiki/status.md) next steps.
- A source identifier is planned on frames, traces and rows before a second source exists.
- Two sources with direction by source wait for the Japanese gate.
- Network microphones and LAN phone readers were dropped; an iPhone is a Continuity input device.

## Not done

- No profile is implemented. Gate values per profile are starting points for the faint-level sweep and the processing on-versus-off room session.
- Virtual loopback input for meeting audio has not been tried with the operator page.
- Open floor runs within one language pair per session; whether the maintainer wants more than two languages in a breakout was raised and left with the single-pair decision.
